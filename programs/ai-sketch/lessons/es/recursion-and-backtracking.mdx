## Fundamentos de la recursividad

Una función recursiva se llama a sí misma con una versión **más pequeña** del problema hasta que llega a un **caso base** que detiene la cadena.

Cada recursividad necesita dos cosas:
1. **Caso base**: la entrada más simple a la que regresa directamente.
2. **Caso recursivo**: analice el problema y llámese usted mismo.

```python
def factorial(n):
    if n <= 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case
```

## La pila de llamadas: visualizada

Cada llamada recursiva empuja un marco a la pila de llamadas. Cuando regresa el caso base, los fotogramas aparecen en orden inverso.

```
factorial(4)
  → factorial(3)
    → factorial(2)
      → factorial(1) → returns 1
    ← returns 2
  ← returns 6
← returns 24
```

Si no hay un caso base, la pila se desborda. El límite de recursividad predeterminado de Python es 1000 fotogramas.

<FunFact>El límite de recursividad predeterminado de Python de 1000 es intencionalmente conservador. Puede generarlo con sys.setrecursionlimit(), pero generalmente se prefieren las soluciones iterativas para una recursividad profunda.</FunFact>

## Fibonacci - La trampa clásica

El ingenuo Fibonacci recursivo es O(2ⁿ) porque vuelve a calcular los mismos subproblemas. La memorización soluciona esto en O(n) tiempo y espacio.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

## Retroceder: probar todo y luego deshacer

Retroceder es recursividad con un giro: usted **hace una elección**, recurre y luego **deshace la elección** antes de probar la siguiente opción. Piense en ello como si estuviera explorando un laberinto: camine hacia adelante, llegue a un callejón sin salida, retroceda, intente el siguiente camino.

### La plantilla de retroceso

```python
def backtrack(state, choices):
    if is_solution(state):
        result.append(state.copy())
        return
    for choice in choices:
        if is_valid(choice):
            state.add(choice)       # choose
            backtrack(state, ...)   # explore
            state.remove(choice)    # un-choose
```

Este patrón de tres pasos (**elegir, explorar, no elegir**) es la columna vertebral de casi todos los problemas de retroceso.

## Permutaciones

Genere todos los pedidos de `[1, 2, 3]`. En cada nivel, elija un número no utilizado, recurra y luego deseleccione.

```
         []
      /   |   \
    [1]  [2]  [3]
    / \   ...
 [1,2] [1,3]
   |      |
[1,2,3] [1,3,2]  ... (6 total)
```

Hay **n!** permutaciones, por lo que la complejidad del tiempo es O (n × n!).

## Combinaciones y Subconjuntos

**Combinaciones (n elija k):** en cada elemento, inclúyalo u omítalo, pero solo recurra hacia adelante para evitar duplicados.

**Subconjuntos:** la misma idea sin restricción de tamaño: cada nodo en el árbol de recursividad es un subconjunto válido. Hay **2ⁿ** subconjuntos.

<ThinkAboutIt>Las permutaciones producen n! resultados mientras que los subconjuntos producen 2ⁿ. Para n=10, eso es 3.628.800 frente a 1.024, una diferencia enorme. ¿Por qué?</ThinkAboutIt>

## N-Queens - Tutorial

Coloca N reinas en un tablero de N × N para que ninguna se ataque entre sí. Para N=4:

```
. Q . .
. . . Q
Q . . .
. . Q .
```

**Estrategia:** colocar una reina por fila. Para cada fila, pruebe con cada columna. Verifique los conflictos de columnas, diagonales principales y antidiagonales. Si es seguro, colóquelo y recurra a la siguiente fila. Si está atascado, retroceda.

Realice un seguimiento de los conflictos con tres conjuntos: `cols`, `diag` (fila - columna) y `anti_diag` (fila + columna).

## Solucionador de Sudoku - Concepto

Busque una celda vacía, pruebe con los dígitos del 1 al 9. Para cada dígito, verifique las restricciones de fila, columna y cuadro de 3 × 3. Si es válido, coloque y recurra. Si ningún dígito funciona, deshaga y retroceda. La eliminación de restricciones lo hace manejable a pesar del enorme espacio de búsqueda.

## Búsqueda de palabras en una cuadrícula

Dado un tablero de letras 2D y una palabra objetivo, comience desde cada celda y DFS en cuatro direcciones, haciendo coincidir un carácter a la vez. Marque las celdas como visitadas durante la recursividad y **desmarque al retroceder** para permitir otras rutas.

## Complejidad temporal del retroceso

El costo depende del **factor de ramificación** (elecciones por paso) y la **profundidad** (pasos para una solución). Para b ramas yd profundidad: O(bᵈ).

| Problema | Ramificación | Profundidad | Complejidad |
|---------|-----------|-------|------------|
| Permutaciones | norte, norte−1,… | norte | O(n!) |
| Subconjuntos | 2 | norte | O(2ⁿ) |
| N-Reinas | ~norte | norte | O(n!) peor caso |

## Poda para optimizar

**Podar** significa omitir ramas que sabes que fallarán. Ejemplos:
- N-Queens: salta columnas ya ocupadas.
- Sudoku: omite dígitos que violen las restricciones.
- Suma combinada: omitir si la suma restante <0.

Una buena poda puede convertir una búsqueda poco práctica en una rápida.
