## రికర్షన్ పునాదులు

రికర్సివ్ ఫంక్షన్ **బేస్ కేసు** చేరుకునే వరకు సమస్య యొక్క **చిన్న** రూపంతో తనను తాను కాల్ చేసుకుంటుంది.

ప్రతి రికర్షన్ కి రెండు విషయాలు కావాలి:
1. **బేస్ కేసు** - నేరుగా రిటర్న్ చేసే సరళమైన ఇన్‌పుట్.
2. **రికర్సివ్ కేసు** - సమస్యను విభజించి తనను తాను కాల్ చేసుకోవడం.

```python
def factorial(n):
    if n <= 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case
```

## కాల్ స్టాక్ - దృశ్యీకరణ

ప్రతి రికర్సివ్ కాల్ కాల్ స్టాక్ పైకి ఫ్రేమ్ పుష్ చేస్తుంది. బేస్ కేసు రిటర్న్ అయినప్పుడు, ఫ్రేమ్‌లు రివర్స్ క్రమంలో పాప్ అవుతాయి.

```
factorial(4)
  → factorial(3)
    → factorial(2)
      → factorial(1) → 1 return చేస్తుంది
    ← 2 return చేస్తుంది
  ← 6 return చేస్తుంది
← 24 return చేస్తుంది
```

బేస్ కేసు లేకపోతే, స్టాక్ ఓవర్‌ఫ్లో అవుతుంది. Python డిఫాల్ట్ రికర్షన్ పరిమితి 1,000 ఫ్రేమ్‌లు.

<FunFact>Python 1,000 రికర్షన్ పరిమితి ఉద్దేశపూర్వకంగా జాగ్రత్తగా. sys.setrecursionlimit() తో పెంచవచ్చు, కానీ లోతైన రికర్షన్ కి ఇటరేటివ్ పరిష్కారాలు సాధారణంగా ఇష్టపడతారు.</FunFact>

## Fibonacci - క్లాసిక్ ఉచ్చు

Naïve రికర్సివ్ Fibonacci O(2ⁿ) ఎందుకంటే ఇది అదే ఉపసమస్యలు ను మళ్ళీ మళ్ళీ గణించండి చేస్తుంది. మెమోయిజేషన్ దీన్ని O(n) సమయం మరియు అంతరిక్షంలో పరిష్కరిస్తుంది.

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

## బ్యాక్‌ట్రాకింగ్ - అన్నీ ప్రయత్నించు, తర్వాత రద్దు చేయి

బ్యాక్‌ట్రాకింగ్ అనేది మలుపు తో రికర్షన్: మీరు **ఎంపిక చేసి**, రికర్స్ చేసి, తదుపరి ఎంపిక ప్రయత్నించే ముందు **ఎంపికను రద్దు చేస్తారు**. మేజ్ అన్వేషించు చేయడం అనుకోండి - ముందుకు నడవండి, మూసుకుపోయిన దారి తగిలితే వెనక్కి, తదుపరి పాత్ ప్రయత్నించండి.

### బ్యాక్‌ట్రాకింగ్ టెంప్లేట్

```python
def backtrack(state, choices):
    if is_solution(state):
        result.append(state.copy())
        return
    for choice in choices:
        if is_valid(choice):
            state.add(choice)       # ఎంచుకో
            backtrack(state, ...)   # explore చేయి
            state.remove(choice)    # రద్దు చేయి
```

ఈ మూడు-దశల నమూనా - **ఎంచుకో, అన్వేషించు చేయి, రద్దు చేయి** - దాదాపు ప్రతి బ్యాక్‌ట్రాకింగ్ సమస్య యొక్క వెన్నెముక.

## పర్మ్యూటేషన్లు

`[1, 2, 3]` యొక్క అన్ని వరుసక్రమాలు సృష్టించు చేయండి. ప్రతి స్థాయి లో, ఉపయోగించని సంఖ్య ఎంచుకోండి, రికర్స్ చేయండి, తర్వాత ఎంపికను తీసేయండి చేయండి.

```
         []
      /   |   \
    [1]  [2]  [3]
    / \   ...
 [1,2] [1,3]
   |      |
[1,2,3] [1,3,2]  ... (6 మొత్తం)
```

**n!** పర్మ్యూటేషన్లు ఉంటాయి, కాబట్టి సమయ సంక్లిష్టత O(n × n!).

## కాంబినేషన్లు మరియు ఉపసమితులు

**కాంబినేషన్లు (n ఎంచుకోండి k):** ప్రతి ఎలిమెంట్ వద్ద, దాన్ని చేర్చండి లేదా దాటవేయండి చేయండి, నకళ్లు నివారించడానికి ముందుకు మాత్రమే రికర్స్ చేయండి.

**ఉపసమితులు:** పరిమాణం నియమం లేకుండా అదే ఆలోచన - రికర్షన్ ట్రీ లో ప్రతి నోడ్ చెల్లుబాటు అయ్యే ఉపసమితి. **2ⁿ** ఉపసమితులు ఉంటాయి.

<ThinkAboutIt>పర్మ్యూటేషన్లు n! ఫలితాలు ఇస్తాయి, ఉపసమితులు 2ⁿ ఇస్తాయి. n=10 కి, అది 3,628,800 vs 1,024 - భారీ తేడా. ఎందుకు?</ThinkAboutIt>

## N-క్వీన్స్ - వివరణ

N×N బోర్డు పై N రాణులు ను ఒకరినొకరు దాడి చేయకుండా ఉంచండి. N=4 కి:

```
. Q . .
. . . Q
Q . . .
. . Q .
```

**వ్యూహం:** ప్రతి వరుస కి ఒక రాణి ఉంచండి. ప్రతి వరుస కి ప్రతి కాలమ్ ప్రయత్నించండి. కాలమ్, ప్రధాన కర్ణం మరియు వ్యతిరేక కర్ణం ఘర్షణలు తనిఖీ చేయండి. సురక్షితం అయితే ఉంచి తదుపరి వరుస కి రికర్స్ చేయండి. ఇరుక్కుంది అయితే బ్యాక్‌ట్రాక్.

మూడు సెట్‌లు తో ఘర్షణలు ట్రాక్ చేయండి: `cols`, `diag` (వరుస − కాలమ్) మరియు `anti_diag` (వరుస + కాలమ్).

## సుడోకు పరిష్కారకుడు - భావన

ఖాళీ సెల్ కనుగొని, 1-9 అంకెలు ప్రయత్నించండి. ప్రతి అంకె కి వరుస, కాలమ్ మరియు 3×3 బాక్స్ నియమాలు తనిఖీ చేయండి. సరైనది అయితే ఉంచి రికర్స్ చేయండి. ఏ అంకె పనిచేయకపోతే, అన్‌డూ చేసి బ్యాక్‌ట్రాక్. నియమాలు నుండి ప్రూనింగ్ భారీ సెర్చ్ స్థలం ఉన్నప్పటికీ దీన్ని సాధ్యం చేస్తుంది.

## గ్రిడ్ లో పదం సెర్చ్

2D అక్షరాలు బోర్డు మరియు లక్ష్యం పదం ఇచ్చినప్పుడు, ప్రతి సెల్ నుండి ప్రారంభించి నాలుగు దిశలలో DFS చేయండి, ఒక అక్షరం చొప్పున సరిపోలిక చేస్తూ. రికర్షన్ సమయంలో సెల్‌లు ను సందర్శించిన గా గుర్తు చేసి, **బ్యాక్‌ట్రాక్ చేసేటప్పుడు గుర్తు తొలగించు** చేయండి.

## బ్యాక్‌ట్రాకింగ్ యొక్క సమయ సంక్లిష్టత

ఖర్చు **శాఖల సంఖ్య** (ప్రతి దశ లో ఎంపికలు) మరియు **లోతు** (solution కి దశలు) పై ఆధారపడుతుంది. b శాఖలు మరియు d లోతు కి: O(bᵈ).

| సమస్య | శాఖల విస్తరణ | లోతు | సంక్లిష్టత |
|--------|-----------|-------|------------|
| పర్మ్యూటేషన్లు | n, n−1, … | n | O(n!) |
| ఉపసమితులు | 2 | n | O(2ⁿ) |
| N-క్వీన్స్ | ~n | n | O(n!) చెత్త పరిస్థితి |

## ప్రూనింగ్ ద్వారా ఆప్టిమైజేషన్

**ప్రూనింగ్** అంటే విఫలమవుతాయని తెలిసిన శాఖలు ను దాటవేయండి చేయడం. ఉదాహరణలు:
- N-క్వీన్స్: ఇప్పటికే ఆక్రమించిన కాలమ్‌లు దాటవేయండి.
- సుడోకు: నియమాలు ఉల్లంఘించే అంకెలు దాటవేయండి.
- కాంబినేషన్ మొత్తం: మిగిలిన మొత్తం < 0 అయితే దాటవేయండి.

మంచి ప్రూనింగ్ అసాధ్యమైన సెర్చ్ ను వేగవంతమైనదిగా మార్చగలదు.
