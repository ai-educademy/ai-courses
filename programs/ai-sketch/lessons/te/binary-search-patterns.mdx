## క్లాసిక్ బైనరీ సెర్చ్ - త్వరిత సమీక్ష

బైనరీ సెర్చ్ ప్రతి అడుగులో సెర్చ్ స్థలం ను సగానికి తగ్గిస్తుంది. n ఎలిమెంట్ల సార్టెడ్ అర్రే లో **O(లాగ్ n)** సమయంలో లక్ష్యాన్ని కనుగొంటుంది.

```python
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

సరళంగా ఉంది - కానీ బైనరీ సెర్చ్ యొక్క నిజమైన శక్తి సార్టెడ్ అర్రేలు కంటే చాలా దూరం వెళ్తుంది.

## సెర్చ్ స్థలం భావన

మీ దగ్గర ఒక పరిధిలో **monotonic condition** ఉన్నప్పుడు బైనరీ సెర్చ్ పనిచేస్తుంది. "అర్రే" ఉండాల్సిన అవసరం కూడా లేదు - మీకు `[lo, hi]` పరిధి మరియు ఏదో సరిహద్దు వద్ద `తప్పుడు` నుండి `True` కు మారే ఫంక్షన్ మాత్రమే కావాలి.

```
Search space:  [lo .................. hi]
Condition:      F  F  F  F  T  T  T  T
                          ^-- సమాధానం
```

## సమాధానం పై బైనరీ సెర్చ్

అర్రే లో వెతకడానికి బదులు, **సమాధానం స్థలం** లో వెతకండి. ప్రశ్న: "నేను X ఫలితాన్ని సాధించగలనా?" అవును అయితే, చిన్నది ప్రయత్నించండి; కాదంటే, పెద్దది ప్రయత్నించండి.

### ఉదాహరణ: Koko Eating Bananas

Koko దగ్గర `n` అరటి గుట్టలు మరియు `h` గంటలు ఉన్నాయి. ఆమె సమయానికి పూర్తి చేయడానికి **కనీస తినే వేగం** కనుగొనండి.

```python
def min_speed(piles, h):
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        hours = sum((p + mid - 1) // mid for p in piles)
        if hours <= h:
            hi = mid      # వేగం పనిచేస్తుంది, నెమ్మదిగా ప్రయత్నించు
        else:
            lo = mid + 1  # చాలా నెమ్మది, వేగంగా వెళ్ళు
    return lo
```

సమాధానం స్థలం `[1, max(piles)]` మరియు condition monotonic - ఎక్కువ వేగం అంటే ఎల్లప్పుడూ తక్కువ గంటలు.

## Rotated సార్టెడ్ అర్రే

ఒక pivot వద్ద తిప్పండి చేసిన సార్టెడ్ అర్రే: `[4, 5, 6, 7, 0, 1, 2]`. ఒక సగం ఎల్లప్పుడూ సార్టెడ్ గా ఉంటుంది. ఏ సగమో నిర్ణయించడానికి `mid` ని `lo` తో పోల్చండి, తర్వాత లక్ష్యం సార్టెడ్ సగంలో ఉందో లేదో తనిఖీ చేయండి.

```
[4, 5, 6, 7, 0, 1, 2]
 L        M        R
ఎడమ సగం [4..7] sorted గా ఉంది.
లక్ష్యం 1 [4..7] లో లేదు → కుడి వైపు వెతకండి.
```

## మొదటి మరియు చివరి సంఘటన

**మొదటి** సంఘటన కనుగొనడానికి: లక్ష్యం దొరికినప్పుడు, ఆగకండి - `hi = mid` సెట్ చేసి ఎడమ వైపు వెతకడం కొనసాగించండి. **చివరి** కోసం, `lo = mid + 1` సెట్ చేసి కుడి వైపు వెతకండి.

ఈ జత శోధనలు లక్ష్యం యొక్క **సంఖ్యను** కూడా ఇస్తుంది: `last - first + 1`.

## Peak ఎలిమెంట్

రెండు పొరుగువారి కంటే పెద్ద ఎలిమెంట్. సార్ట్ చేయని అర్రే లో కూడా బైనరీ సెర్చ్ పనిచేస్తుంది: `nums[mid] < nums[mid + 1]` అయితే, peak కుడి వైపు ఉంటుంది; లేకపోతే ఎడమ వైపు. O(లాగ్ n).

<ThinkAboutIt>అర్రే సార్టెడ్ కాకపోయినా peak-finding బైనరీ సెర్చ్ తో ఎందుకు పనిచేస్తుంది? సార్టెడ్ క్రమం స్థానంలో ఇక్కడ ఏ ఆస్తి ఉంటుంది?</ThinkAboutIt>

## 2D మ్యాట్రిక్స్ లో వెతకడం

వరుసలు సార్టెడ్ అయి ఉండి, ప్రతి వరుస మొదటి ఎలిమెంట్ ముందటి వరుస చివరి దాని కంటే పెద్దది అయితే, మ్యాట్రిక్స్ ను `m × n` ఎలిమెంట్‌లు ఉన్న ఒకే సార్టెడ్ అర్రే గా చూడండి. ఇండెక్స్ `k` ను వరుస `k // n`, కాలమ్ `k % n` గా మార్చండి.

## లైబ్రరీ లేకుండా వర్గమూలం

`x * x ≤ n` అయ్యే అతిపెద్ద పూర్ణాంకం `x` కనుగొనండి. సెర్చ్ స్థలం: `[0, n]`. క్లాసిక్ బైనరీ సెర్చ్ on సమాధానం.

```python
def sqrt(n):
    lo, hi = 0, n
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi
```

## "గరిష్టాన్ని కనిష్టం చేయి" పాటర్న్

"విభజించు అర్రే largest మొత్తం" లేదా "D రోజుల్లో packages పంపే సామర్థ్యం" వంటి సమస్యలు **చెత్త సందర్భాన్ని కనిష్టం చేయమని** అడుగుతాయి. సమాధానం monotonic: సామర్థ్యం C పనిచేస్తే, C+1 కూడా పనిచేస్తుంది. C పై బైనరీ సెర్చ్.

## సార్వత్రిక Template

```python
lo, hi = min_possible, max_possible
while lo < hi:
    mid = (lo + hi) // 2
    if condition(mid):
        hi = mid        # mid పనిచేస్తుంది, చిన్నది ప్రయత్నించు
    else:
        lo = mid + 1    # mid విఫలం, పెద్దది కావాలి
return lo
```

మీరు **మొదటి True** వెతుకుతున్నారా లేదా **చివరి True** వెతుకుతున్నారా అనేదాన్ని బట్టి `hi = mid` vs `lo = mid` సర్దుబాటు చేయండి.
