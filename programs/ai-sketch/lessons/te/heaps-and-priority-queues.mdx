## హీప్ అంటే ఏమిటి?

**హీప్** అనేది ప్రతి పేరెంట్ **హీప్ లక్షణం** ని సంతృప్తిపరిచే పూర్తి బైనరీ ట్రీ - ఎల్లప్పుడూ చైల్డ్‌లు కంటే చిన్నది (మిన్-హీప్) లేదా పెద్దది (మ్యాక్స్-హీప్). "పూర్తి" అంటే చివరి స్థాయి తప్ప ప్రతి స్థాయి నిండి ఉంటుంది, చివరిది ఎడమ నుండి కుడికి నిండుతుంది.

```
       1            Min-heap
      / \
     3   5
    / \
   7   4
```

ఇది పూర్తి కాబట్టి, **సమతల అర్రే** లో నిల్వ చేస్తాం - పాయింటర్లు అవసరం లేదు. ఇండెక్స్ `i` కోసం: ఎడమ చైల్డ్ = `2i + 1`, కుడి చైల్డ్ = `2i + 2`, పేరెంట్ = `(i - 1) // 2`.

## మిన్-హీప్ vs మ్యాక్స్-హీప్

| లక్షణం | మిన్-హీప్ | మ్యాక్స్-హీప్ |
|----------|----------|----------|
| రూట్ | అతి చిన్న ఎలిమెంట్ | అతి పెద్ద ఎలిమెంట్ |
| పేరెంట్ ≤ చైల్డ్‌లు? | ✅ అవును | ❌ కాదు (≥) |
| తీయండి ఇస్తుంది | కనిష్ఠం | గరిష్ఠం |

Python `heapq` డిఫాల్ట్‌గా **మిన్-హీప్**. మ్యాక్స్-హీప్ కోసం, చొప్పించేటప్పుడు విలువలను నెగేట్ చేసి, తీసేటప్పుడు మళ్ళీ నెగేట్ చేయండి.

## చొప్పించు మరియు తీయండి - అడుగు అడుగునా

**చొప్పించు** - చివరికి పుష్ చేసి, **బబుల్ up** చేయండి (చిన్నదైనంత వరకు పేరెంట్ తో స్వాప్):

```python
import heapq
h = [1, 3, 5, 7]
heapq.heappush(h, 2)  # h [1, 2, 5, 7, 3] అవుతుంది
```

**తీయండి కనిష్ఠం** - రూట్ ను చివరి ఎలిమెంట్ తో స్వాప్ చేసి, చివరిది తొలగించి, **జల్లెడపట్టు కిందకు** చేయండి (చిన్న చైల్డ్ తో స్వాప్):

```python
smallest = heapq.heappop(h)  # 1 రిటర్న్ చేస్తుంది
```

రెండు ఆపరేషన్లు **O(లాగ్ n)** లో నడుస్తాయి ఎందుకంటే ట్రీ ఎత్తు లాగ్ n.

## హీపిఫై - O(n) లో హీప్ నిర్మించడం

`heapq.heapify(arr)` ను కాల్ చేయడం లిస్ట్ ను **ఇన్-స్థానంలో** O(n) లో హీప్ గా మారుస్తుంది, O(n లాగ్ n) కాదు. ఇది కిందనుంచి పైకి పనిచేస్తుంది, ప్రతి నెగటివ్ కాని ఆకు నోడ్ ను కిందకు జల్లెడపట్టు చేస్తుంది. CS లో అత్యంత ఆశ్చర్యకరమైన సంక్లిష్టత ఫలితాలలో ఇది ఒకటి.

<FunFact>హీప్ నిర్మించడం O(n), O(n లాగ్ n) కాదు. చాలా నోడ్‌లు అడుగున ఉంటాయి మరియు కింద జల్లెడపట్టు అవ్వాల్సిన అవసరం చాలా తక్కువ - గణితం రేఖీయ సమయం ఇస్తుంది.</FunFact>

## ప్రాధాన్యత క్యూ అబ్స్ట్రాక్షన్

**ప్రాధాన్యత క్యూ** మీకు ఎల్లప్పుడూ అత్యధిక-ప్రాధాన్యత అంశం కు ప్రాప్యత ఇస్తుంది. చొప్పించు మరియు తీయండి రెండూ O(లాగ్ n) కాబట్టి హీప్‌లు ఉత్తమ అమలు. "ఇప్పటివరకు ఉత్తమ అంశం ఇవ్వు" అనే అవసరం ఉన్నప్పుడల్లా ఉపయోగించండి.

## పాటర్న్: అగ్ర-K సమస్యలు

> "సార్ట్ చేయని అర్రే లో K అతిపెద్ద ఎలిమెంట్‌లు కనుగొనండి."

**K పరిమాణం మిన్-హీప్** ఉంచండి. ప్రతి ఎలిమెంట్ కోసం పుష్ చేయండి; హీప్ K కంటే పెరిగితే, అతి చిన్నదాన్ని పాప్ చేయండి. మిగిలేవి K అతిపెద్దవి.

```python
import heapq
def top_k(nums, k):
    return heapq.nlargest(k, nums)
```

సమయం: **O(n లాగ్ k)** - k ≪ n అయినప్పుడు సార్టింగ్ కంటే చాలా మెరుగు.

## పాటర్న్: K సార్టెడ్ లిస్ట్‌లు విలీనం చేయడం

ప్రతి లిస్ట్ హెడ్ ను మిన్-హీప్ లో పుష్ చేయండి. అతి చిన్నదాన్ని పాప్ చేసి, ఆ లిస్ట్ నుండి తదుపరి ఎలిమెంట్ ను పుష్ చేయండి. అన్ని లిస్ట్‌లు అయిపోయే వరకు పునరావృతం చేయండి. సమయం: **O(N లాగ్ K)** ఇక్కడ N మొత్తం ఎలిమెంట్‌లు.

## పాటర్న్: డేటా ప్రవాహం నుండి మధ్య విలువ

రెండు హీప్‌లు నిర్వహించండి: దిగువ సగానికి **మ్యాక్స్-హీప్** మరియు ఎగువ సగానికి **మిన్-హీప్**. వాటి పరిమాణాలు గరిష్టంగా 1 తేడా ఉండేలా సమతుల్యం చేయండి. మధ్య విలువ ఎల్లప్పుడూ ఒకటి లేదా రెండు రూట్లు వద్ద ఉంటుంది.

```
దిగువ సగం (max-heap): [1, 2, 3]  ← max = 3
ఎగువ సగం (min-heap): [4, 5, 6]  ← min = 4
Median = (3 + 4) / 2 = 3.5
```

## షెడ్యూలింగ్ సమస్యలు

షెడ్యూలింగ్ లో హీప్‌లు రాణిస్తాయి: సమావేశ గదులు (ముందుగా ముగిసే సమయం ట్రాక్ చేయడం), కూల్‌డౌన్‌లు తో పని షెడ్యూలింగ్, లేదా CPU పని క్యూలు. కీలక అంతర్దృష్టి - హీప్ "తర్వాత ఏది ముగుస్తుంది" అనేదాన్ని సమర్థవంతంగా ట్రాక్ చేస్తుంది.

<ThinkAboutIt>మీకు కనిష్ఠం మరియు గరిష్ఠం రెండూ సమర్థవంతంగా కావాలంటే, ఒకే హీప్ సరిపోదు. ఏ డేటా నిర్మాణం కలయిక ఉపయోగిస్తారు?</ThinkAboutIt>

## హీప్ vs సార్టెడ్ అర్రే vs BST ఎప్పుడు

| అవసరం | ఉత్తమ ఎంపిక | ఎందుకు |
|--------|-------------|--------|
| పునరావృత కనిష్ఠం/గరిష్ఠం తీత | హీప్ | O(లాగ్ n) చొప్పించు + తీయండి |
| స్థిర డేటా, ఒకసారి సార్ట్ | సార్టెడ్ అర్రే | O(n లాగ్ n) ఒకసారి, O(1) ప్రాప్యత |
| పరిధి క్వెరీలు + క్రమం గణాంకాలు | సమతుల్య BST | అన్నింటికీ O(లాగ్ n) |
| ప్రవాహం నుండి అగ్ర-K | K పరిమాణ హీప్ | O(n లాగ్ k) మొత్తం |
