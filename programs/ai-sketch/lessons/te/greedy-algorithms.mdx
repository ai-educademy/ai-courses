## అల్గారిథమ్ ను గ్రీడీ గా ఏది చేస్తుంది?

గ్రీడీ అల్గారిథమ్ ఒక పరిష్కారాన్ని **ఒక్కో అడుగు** గా నిర్మిస్తుంది, ఎల్లప్పుడూ **ఇప్పుడు** ఉత్తమంగా కనిపించే ఎంపికను ఎంచుకుంటుంది - గత ఎంపికలను తిరిగి పరిగణించకుండా. బ్యాక్‌ట్రాకింగ్ లేదు, ముందుకు చూడడం లేదు.

రెండు లక్షణాలు ఉన్నప్పుడు ఇది పనిచేస్తుంది:
1. **గ్రీడీ ఎంపిక లక్షణం** - స్థానికంగా ఉత్తమ ఎంపిక సమగ్రంగా ఉత్తమ పరిష్కారానికి దారితీస్తుంది.
2. **ఉత్తమ substructure** - ప్రతి ఎంపిక తర్వాత మిగిలిన సమస్య అదే సమస్య యొక్క చిన్న రూపం.

## కార్యకలాపం Selection - క్లాసిక్ ఉదాహరణ

ప్రారంభ మరియు ముగింపు సమయాలతో కార్యకలాపాల సమూహం ఇచ్చినప్పుడు, అతిపెక్కు అతివ్యాప్తి కాని కార్యకలాపాలను ఎంచుకోండి.

**గ్రీడీ వ్యూహం:** ముగింపు సమయం ప్రకారం సార్ట్ చేసి, ఎల్లప్పుడూ ముందుగా ముగిసే కార్యకలాపాన్ని ఎంచుకోండి.

```python
def max_activities(intervals):
    intervals.sort(key=lambda x: x[1])
    count, end = 0, 0
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count
```

ఇది ఎందుకు పనిచేస్తుంది? ముందుగా ముగిసే కార్యకలాపాన్ని ఎంచుకోవడం భవిష్యత్ కార్యకలాపాలకు ఎక్కువ స్థలం ఇస్తుంది. మరే ఎంపికా దీని కంటే మెరుగ్గా చేయలేదు.

## హఫ్మాన్ కోడింగ్ - భావన

అత్యంత తక్కువ-ఫ్రీక్వెన్సీ **రెండు** చిహ్నాలను పదేపదే కలపడం ద్వారా ఉత్తమ ప్రిఫిక్స్-ఉచిత binary కోడ్ నిర్మించండి. ఇది గ్రీడీ: ప్రతి అడుగులో, చౌకైన జతను కలపండి. ఫలితం ఒక ట్రీ, ఇందులో తరచుగా వచ్చే చిహ్నాలకు చిన్న codes ఉంటాయి.

<FunFact>హఫ్మాన్ కోడింగ్ JPEG, MP3, మరియు ZIP compression లో ఉపయోగించబడుతుంది. David హఫ్మాన్ దీన్ని 1952 లో విద్యార్థిగా కనుగొన్నాడు - ఇది ఒక హోంవర్క్ అసైన్‌మెంట్!</FunFact>

## జంప్ గేమ్

`nums[i]` ఇండెక్స్ `i` నుండి గరిష్ట జంప్ పొడవు అయిన అర్రే ఇచ్చినప్పుడు, మీరు చివరి ఇండెక్స్ కి చేరుకోగలరా అని నిర్ణయించండి.

**గ్రీడీ విధానం:** ఇప్పటివరకు చేరుకోగల అతి దూర ఇండెక్స్ ను ట్రాక్ చేయండి. ఎడమ నుండి కుడికి స్కాన్ చేయండి - మీరు ఎప్పుడైనా వెనుకబడితే, false రిటర్న్ చేయండి.

```python
def can_jump(nums):
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:
            return తప్పుడు
        farthest = max(farthest, i + jump)
    return True
```

## ఇంధనం స్టేషన్

ఇంధనం స్టేషన్లు ఉన్న వృత్తాకార మార్గంలో ప్రయాణించండి. స్టేషన్ `i` వద్ద `gas[i]` ఇంధనం పొందుతారు మరియు తదుపరి స్టేషన్ కి చేరుకోవడానికి `cost[i]` ఖర్చవుతుంది. circuit పూర్తి చేయగల starting స్టేషన్ కనుగొనండి, లేదా −1 రిటర్న్ చేయండి.

**గ్రీడీ అంతర్దృష్టి:** మొత్తం ఇంధనం ≥ మొత్తం ఖర్చు అయితే, పరిష్కారం ఉంటుంది. Running surplus ట్రాక్ చేయండి; అది సున్నా కంటే తగ్గినప్పుడు, సమాధానం ఆ పాయింట్ **తర్వాత** మొదలవ్వాలి.

## పని Scheduler

ఒకే రకమైన పనులు మధ్య `n` cooldown తో పనులు షెడ్యూల్ చేయండి. **గ్రీడీ:** ఎల్లప్పుడూ అత్యధిక ఫ్రీక్వెన్సీ మిగిలిన పని ను ఎంచుకోండి. సమాధానం గరిష్ట ఫ్రీక్వెన్సీ మరియు ఎన్ని పనులు దాన్ని పంచుకుంటాయి అనే దానిపై ఆధారపడుతుంది.

```
Tasks: A A A B B C, cooldown = 2
Schedule: A B C A B _ A
Total = 7
```

<ThinkAboutIt>పని scheduler లో, అత్యధిక ఫ్రీక్వెన్సీ పని ను ముందుగా ఎంచుకోవడం idle slots ను ఎందుకు తగ్గిస్తుంది? అత్యల్ప ఫ్రీక్వెన్సీ ముందుగా ఎంచుకుంటే ఏమి తప్పు జరుగుతుంది?</ThinkAboutIt>

## Fractional నాప్‌సాక్ vs 0/1 నాప్‌సాక్

**Fractional నాప్‌సాక్:** అంశాల భాగాలు తీసుకోవచ్చు. గ్రీడీ పనిచేస్తుంది - విలువ-ప్రతి-బరువు ప్రకారం సార్ట్ చేసి, ఉత్తమ నిష్పత్తి ముందుగా తీసుకోండి.

**0/1 నాప్‌సాక్:** అంశాలు పూర్తిగా తీసుకోవాలి లేదా వదిలేయాలి. ఇక్కడ గ్రీడీ **విఫలమవుతుంది** ఎందుకంటే బరువైన-కానీ-విలువైన అంశాన్ని వదిలేయడం రెండు తేలికైన వాటిని తీసుకోవడం కంటే అధ్వాన్నంగా ఉండవచ్చు. దీనికి డైనమిక్ ప్రోగ్రామింగ్ అవసరం.

```
Items: (బరువు=3, విలువ=4), (బరువు=2, విలువ=3), (బరువు=2, విలువ=3)
Capacity: 4

Greedy (ఉత్తమ నిష్పత్తి ముందు): item 1 తీసుకుంటుంది (బ=3, వి=4) → 1 మిగిలింది → మిగతాది సరిపోదు → విలువ = 4
Optimal: items 2+3 తీసుకుంటుంది (బ=4, వి=6) → విలువ = 6 ✗ Greedy విఫలం!
```

## గ్రీడీ ఎప్పుడు పనిచేస్తుంది?

✅ గ్రీడీ ఎంపిక లక్షణం నిరూపించగలిగినప్పుడు **పనిచేస్తుంది**:
- ఇంటర్వెల్ షెడ్యూలింగ్, హఫ్మాన్ కోడింగ్, కనిష్ఠం spanning ట్రీలు, Dijkstra's అల్గారిథమ్, ప్రామాణిక నాణెపు విలువలతో చిల్లర

❌ స్థానిక optima సమగ్ర optima గా కలవనప్పుడు **విఫలమవుతుంది**:
- 0/1 నాప్‌సాక్, సాధారణ గ్రాఫ్‌లు లో longest పాత్, travelling salesman

## గ్రీడీ సరైనదని నిరూపించడం - Exchange Argument

ప్రామాణిక పద్ధతి: గ్రీడీ ఎంపిక **ఉపయోగించని** optimum పరిష్కారం ఉందని ఊహించండి. దాని ఎంపికలలో ఒకదాన్ని గ్రీడీ ఎంపికతో **మార్చినా** పరిష్కారం తగ్గదని చూపించండి. ఇది గ్రీడీ కనీసం అంత మంచిదని నిరూపిస్తుంది.

| సరైనది | నిరూపించగలిగితే మాత్రమే | ఎల్లప్పుడూ (సరిగ్గా రూపొందిస్తే) |

అనుమానం ఉంటే, గ్రీడీ తో ప్రారంభించండి - నిరూపించలేకపోతే, DP కి మారండి.

<FunFact>Dijkstra యొక్క చిన్నదైన-పాత్ అల్గారిథమ్ గ్రీడీ - ఇది ఎల్లప్పుడూ సమీపంలోని సందర్శించని నోడ్ ను ప్రాసెస్ చేస్తుంది. ఎడ్జ్ weights non-నెగటివ్ అయినందున ఇది పనిచేస్తుంది, గ్రీడీ ఎంపిక సురక్షితంగా ఉంటుంది.</FunFact>

<ThinkAboutIt>మీకు నాణెపు విలువలు [1, 3, 4] ఇచ్చి 6 కోసం చిల్లర ఇవ్వాలి. గ్రీడీ విధానం 4+1+1=3 నాణేలు ఎంచుకుంటుంది, కానీ ఉత్తమ 3+3=2 నాణేలు. ఈ విలువలలో గ్రీడీ ఎంపిక లక్షణం ని ఏది విచ్ఛిన్నం చేస్తుంది?</ThinkAboutIt>
