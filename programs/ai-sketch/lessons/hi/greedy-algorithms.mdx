## ग्रीडी Algorithm क्या होता है?

ग्रीडी एल्गोरिदम समाधान **एक कदम** एक बार बनाता है, हमेशा वो option चुनता है जो **अभी** सबसे अच्छा लगे - बिना पुराने फ़ैसले पर दोबारा सोचे। न बैकट्रैकिंग, न आगे देखना।

यह तब काम करता है जब दो properties हों:
1. **ग्रीडी चयन गुण** - स्थानीय रूप से सर्वोत्तम चयन वैश्विक रूप से सर्वोत्तम समाधान तक ले जाए।
2. **Optimal substructure** - हर चयन के बाद बचा समस्या उसी समस्या का छोटा संस्करण हो।

## Activity Selection - क्लासिक उदाहरण

Activities दी हैं जिनके start और अंत times हैं। **अधिकतम** बिना ओवरलैप गतिविधियाँ चुनो।

**ग्रीडी रणनीति:** अंत समय से सॉर्ट करो, हमेशा सबसे पहले खत्म होने वाली गतिविधि चुनो।

```python
def max_activities(intervals):
    intervals.sort(key=lambda x: x[1])
    count, end = 0, 0
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count
```

यह क्यों काम करता है? सबसे पहले खत्म होने वाली गतिविधि चुनने से बाकी गतिविधियाँ के लिए सबसे ज़्यादा जगह बचती है।

## Huffman Coding - अवधारणा

Optimal prefix-मुक्त बाइनरी कोड बनाने के लिए बार-बार **दो सबसे कम आवृत्ति** वाले चिह्न मर्ज करो। यह ग्रीडी है: हर कदम पर सबसे सस्ती जोड़ी मर्ज करो। Result एक ट्री है जहाँ बार-बार चिह्न को छोटे codes मिलते हैं।

<FunFact>Huffman कोडिंग JPEG, MP3, और ZIP compression में इस्तेमाल होती है। David Huffman ने इसे 1952 में एक विद्यार्थी के रूप में ईजाद किया - यह एक homework assignment था!</FunFact>

## Jump गेम

ऐरे दिया है जहाँ `nums[i]` इंडेक्स `i` से अधिकतम जंप लंबाई है। बताओ आख़िरी इंडेक्स तक पहुँच सकते हो या नहीं।

**ग्रीडी तरीका:** अब तक पहुँचने योग्य सबसे दूर इंडेक्स ट्रैक करो। बायाँ से दायाँ स्कैन करो - अगर कभी पीछे रह गए, लौटाएँ गलत।

```python
def can_jump(nums):
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
    return True
```

## Gas स्टेशन

Circular रूट पर गैस stations हैं। स्टेशन `i` पर `gas[i]` fuel मिलता है और अगले स्टेशन तक `cost[i]` खर्च होता है। वो शुरुआती स्टेशन ढूँढो जिससे पूरा circuit पूर्ण हो, या −1 लौटाएँ करो।

**ग्रीडी insight:** अगर कुल गैस ≥ कुल लागत, तो समाधान ज़रूर है। Running surplus ट्रैक करो; जब भी यह नकारात्मक हो, उत्तर उसके **बाद** से शुरू होगा।

## काम Scheduler

Tasks schedule करने हैं जिनमें identical काम के बीच `n` cooldown हो। **ग्रीडी:** हमेशा सबसे बार-बार बाकी काम चुनो।

```
Tasks: A A A B B C, cooldown = 2
Schedule: A B C A B _ A
Total = 7
```

<ThinkAboutIt>काम scheduler में सबसे बार-बार काम पहले चुनने से idle slots कम क्यों होते हैं? अगर सबसे कम बार-बार पहले चुनें तो क्या गलत होगा?</ThinkAboutIt>

## Fractional नैपसैक vs 0/1 नैपसैक

**Fractional नैपसैक:** आइटम के टुकड़े ले सकते हो। ग्रीडी काम करता है - मान-per-भार से सॉर्ट करो, सर्वश्रेष्ठ अनुपात पहले लो।

**0/1 नैपसैक:** आइटम पूरा लो या छोड़ो। ग्रीडी यहाँ **असफल** करता है क्योंकि भारी-but-valuable आइटम छोड़ना दो हल्के आइटम लेने से बुरा हो सकता है। इसके लिए डायनैमिक प्रोग्रामिंग चाहिए।

```
Items: (weight=3, value=4), (weight=2, value=3), (weight=2, value=3)
Capacity: 4

Greedy (best ratio first): item 1 (w=3, v=4) → 1 बचा → बाकी fit नहीं → value = 4
Optimal: items 2+3 (w=4, v=6) → value = 6 ✗ Greedy fail!
```

## ग्रीडी कब काम करता है?

✅ **काम करता है** जब ग्रीडी चयन गुण सिद्ध हो सके:
- Interval शेड्यूलिंग, Huffman कोडिंग, न्यूनतम spanning ट्री, Dijkstra's एल्गोरिदम

❌ **Fail** जब local ऑप्टिमा global ऑप्टिमा न बनाएँ:
- 0/1 नैपसैक, longest रास्ता, travelling salesman

## ग्रीडी शुद्धता - Exchange Argument

Standard technique: मान लो एक सर्वोत्तम समाधान है जो ग्रीडी चयन **नहीं** इस्तेमाल करता। दिखाओ कि उसकी एक चयन को ग्रीडी चयन से **exchange** करने पर समाधान बुरा नहीं होता। इससे साबित होता है ग्रीडी कम से कम उतना ही अच्छा है।

## ग्रीडी vs डायनैमिक प्रोग्रामिंग

| पहलू | ग्रीडी | डायनैमिक प्रोग्रामिंग |
|-------|--------|---------------------|
| चयन | हर कदम पर एक सर्वश्रेष्ठ चयन | सभी उप-समस्याएँ समझते हैं करो |
| Past revisit? | कभी नहीं | हाँ - उप-नतीजे संग्रहीत करता है |
| Speed | आमतौर पर तेज़ | State जगह पर निर्भर |
| शुद्धता | सिर्फ अगर सिद्ध हो | हमेशा (सही formulation पर) |

Doubt हो तो ग्रीडी से शुरू करो - सिद्ध नहीं कर पाए तो DP पर switch करो।

<FunFact>Dijkstra's सबसे छोटा-रास्ता एल्गोरिदम ग्रीडी है - हमेशा closest unvisited node प्रोसेस करता है। यह काम करता है क्योंकि एज weights non-नकारात्मक हैं, जो ग्रीडी चयन को safe बनाता है।</FunFact>

<ThinkAboutIt>Coin मूल्यवर्ग [1, 3, 4] हैं और 6 के लिए change बनाना है। ग्रीडी 4+1+1=3 सिक्के चुनता है, लेकिन सर्वोत्तम 3+3=2 सिक्के है। इन मूल्यवर्ग में ग्रीडी चयन गुण क्यों टूटती है?</ThinkAboutIt>
