## ग्रीडी एल्गोरिदम क्या होता है?

ग्रीडी एल्गोरिदम समाधान **एक कदम** एक बार बनाता है, हमेशा वो विकल्प चुनता है जो **अभी** सबसे अच्छा लगे - बिना पुराने फ़ैसले पर दोबारा सोचे। न बैकट्रैकिंग, न आगे देखना।

यह तब काम करता है जब दो properties हों:
1. **ग्रीडी चयन गुण** - स्थानीय रूप से सर्वोत्तम चयन वैश्विक रूप से सर्वोत्तम समाधान तक ले जाए।
2. **उत्तम उप-संरचना** - हर चयन के बाद बचा समस्या उसी समस्या का छोटा संस्करण हो।

## गतिविधि चयन - क्लासिक उदाहरण

गतिविधियाँ दी हैं जिनके शुरू और खत्म होने के समय हैं। **अधिकतम** बिना ओवरलैप गतिविधियाँ चुनो।

**ग्रीडी रणनीति:** अंत समय से सॉर्ट करो, हमेशा सबसे पहले खत्म होने वाली गतिविधि चुनो।

```python
def max_activities(intervals):
    intervals.sort(key=lambda x: x[1])
    count, end = 0, 0
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count
```

यह क्यों काम करता है? सबसे पहले खत्म होने वाली गतिविधि चुनने से बाकी गतिविधियाँ के लिए सबसे ज़्यादा जगह बचती है।

## Huffman coding - अवधारणा

उत्तम prefix-मुक्त binary code बनाने के लिए बार-बार **दो सबसे कम आवृत्ति** वाले symbols merge करें। यह greedy है: हर कदम पर सबसे सस्ती जोड़ी merge करें। नतीजा एक tree है जहाँ बार-बार आने वाले symbols को छोटे codes मिलते हैं।

<FunFact>Huffman coding JPEG, MP3 और ZIP compression में इस्तेमाल होती है। David Huffman ने इसे 1952 में एक विद्यार्थी के रूप में ईजाद किया - यह एक homework assignment था!</FunFact>

## Jump game

ऐरे दिया है जहाँ `nums[i]` इंडेक्स `i` से अधिकतम जंप लंबाई है। बताओ आख़िरी इंडेक्स तक पहुँच सकते हो या नहीं।

**ग्रीडी तरीका:** अब तक पहुँचने योग्य सबसे दूर इंडेक्स ट्रैक करो। बायाँ से दायाँ स्कैन करो - अगर कभी पीछे रह गए, लौटाएँ गलत।

```python
def can_jump(nums):
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
    return True
```

## Gas station

गोल route पर gas stations हैं। station `i` पर `gas[i]` fuel मिलता है और अगले station तक `cost[i]` खर्च होता है। वह starting station ढूँढो जिससे पूरा circuit पूरा हो, या -1 लौटाएँ।

**ग्रीडी insight:** अगर कुल gas ≥ कुल cost, तो solution ज़रूर है। running surplus track करें; जब भी यह negative हो, answer उसके **बाद** से शुरू होगा।

## काम scheduler

tasks schedule करने हैं जिनमें एक जैसे tasks के बीच `n` cooldown हो। **ग्रीडी:** हमेशा सबसे बार-बार बाकी काम चुनो।

```
Tasks: A A A B B C, cooldown = 2
Schedule: A B C A B _ A
कुल = 7
```

<ThinkAboutIt>काम scheduler में सबसे बार-बार आने वाला task पहले चुनने से idle slots कम क्यों होते हैं? अगर सबसे कम बार-बार पहले चुनें तो क्या गलत होगा?</ThinkAboutIt>

## fractional knapsack vs 0/1 knapsack

**fractional knapsack:** आइटम के टुकड़े ले सकते हो। ग्रीडी काम करता है - value-per-weight से सॉर्ट करो, सर्वश्रेष्ठ अनुपात पहले लो।

**0/1 knapsack:** आइटम पूरा लो या छोड़ो। ग्रीडी यहाँ **असफल** करता है क्योंकि भारी लेकिन मूल्यवान आइटम छोड़ना दो हल्के आइटम लेने से बुरा हो सकता है। इसके लिए dynamic programming चाहिए।

```
Items: (weight=3, value=4), (weight=2, value=3), (weight=2, value=3)
Capacity: 4

Greedy (best ratio first): item 1 (w=3, v=4) → 1 बचा → बाकी fit नहीं → value = 4
Optimal: items 2+3 (w=4, v=6) → value = 6 ✗ Greedy fail!
```

## ग्रीडी कब काम करता है?

✅ **काम करता है** जब ग्रीडी चयन गुण सिद्ध हो सके:
- interval scheduling, Huffman coding, minimum spanning tree, Dijkstra's algorithm

❌ असफल जब local optima global optima न बनाएँ:
- 0/1 knapsack, सबसे लंबा रास्ता, travelling salesman

## ग्रीडी शुद्धता - exchange argument

मानक तकनीक: मान लो एक सर्वोत्तम समाधान है जो ग्रीडी चयन **नहीं** इस्तेमाल करता। दिखाओ कि उसकी एक चयन को ग्रीडी चयन से **exchange** करने पर समाधान बुरा नहीं होता। इससे साबित होता है ग्रीडी कम से कम उतना ही अच्छा है।

## ग्रीडी vs dynamic programming

| पहलू | ग्रीडी | dynamic programming |
|-------|--------|---------------------|
| चयन | हर कदम पर एक सर्वश्रेष्ठ चयन | सभी उप-समस्याएँ समझते हैं करो |
| पुराने फ़ैसले दोबारा? | कभी नहीं | हाँ - उप-नतीजे संग्रहीत करता है |
| गति | आमतौर पर तेज़ | state space पर निर्भर |
| शुद्धता | सिर्फ अगर सिद्ध हो | हमेशा (सही formulation पर) |

संदेह हो तो ग्रीडी से शुरू करो - सिद्ध नहीं कर पाए तो DP पर जाएँ करो।

<FunFact>Dijkstra's shortest path algorithm greedy है - हमेशा सबसे नज़दीकी unvisited node process करता है। यह काम करता है क्योंकि edge weights non-negative हैं, जो greedy selection को सुरक्षित बनाते हैं।</FunFact>

<ThinkAboutIt>coin denominations [1, 3, 4] हैं और 6 के लिए change बनाना है। ग्रीडी 4+1+1=3 सिक्के चुनता है, लेकिन सर्वोत्तम 3+3=2 सिक्के है। इन मूल्यवर्ग में ग्रीडी चयन गुण क्यों टूटती है?</ThinkAboutIt>
