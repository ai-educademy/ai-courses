## ग्रीडी एल्गोरिदम क्या होता है?

ग्रीडी एल्गोरिदम समाधान **एक कदम** एक बार बनाता है, हमेशा वो विकल्प चुनता है जो **अभी** सबसे अच्छा लगे - बिना पुराने फ़ैसले पर दोबारा सोचे। न बैकट्रैकिंग, न आगे देखना।

यह तब काम करता है जब दो गुण हों:
1. **ग्रीडी चयन गुण** - स्थानीय रूप से सर्वोत्तम चयन वैश्विक रूप से सर्वोत्तम समाधान तक ले जाए।
2. **सर्वोत्तम सुबसटरुकटुरे** - हर चयन के बाद बचा समस्या उसी समस्या का छोटा संस्करण हो।

## गतिविधि चयन - क्लासिक उदाहरण

गतिविधियाँ दी हैं जिनके शुरू और अंत समय हैं। **अधिकतम** बिना ओवरलैप गतिविधियाँ चुनो।

**ग्रीडी रणनीति:** अंत समय से सॉर्ट करो, हमेशा सबसे पहले खत्म होने वाली गतिविधि चुनो।

```python
def max_activities(intervals):
    intervals.sort(key=lambda x: x[1])
    count, end = 0, 0
    for s, e in intervals:
        if s >= end:
            count += 1
            end = e
    return count
```

यह क्यों काम करता है? सबसे पहले खत्म होने वाली गतिविधि चुनने से बाकी गतिविधियाँ के लिए सबसे ज़्यादा जगह बचती है।

## हुफफपुरुष कोडिंग - अवधारणा

सर्वोत्तम परेफिक्समुक्त बाइनरी कोड बनाने के लिए बार-बार **दो सबसे कम आवृत्ति** वाले चिह्न मर्ज करो। यह ग्रीडी है: हर कदम पर सबसे सस्ती जोड़ी मर्ज करो। नतीजा एक ट्री है जहाँ बार-बार चिह्न को छोटे कोड मिलते हैं।

<FunFact>हुफफपुरुष कोडिंग JPEG, MP3, और ZIP संपीड़न में इस्तेमाल होती है। डअविड हुफफपुरुष ने इसे 1952 में एक विद्यार्थी के रूप में ईजाद किया - यह एक गृहकार्य असाइनमेंट था!</FunFact>

## जंप गेम

ऐरे दिया है जहाँ `nums[i]` इंडेक्स `i` से अधिकतम जंप लंबाई है। बताओ आख़िरी इंडेक्स तक पहुँच सकते हो या नहीं।

**ग्रीडी तरीका:** अब तक पहुँचने योग्य सबसे दूर इंडेक्स ट्रैक करो। बायाँ से दायाँ स्कैन करो - अगर कभी पीछे रह गए, लौटाएँ गलत।

```python
def can_jump(nums):
    farthest = 0
    for i, jump in enumerate(nums):
        if i > farthest:
            return False
        farthest = max(farthest, i + jump)
    return True
```

## गैस स्टेशन

गोलाकार रूट पर गैस स्टेशन हैं। स्टेशन `i` पर `gas[i]` ईंधन मिलता है और अगले स्टेशन तक `cost[i]` खर्च होता है। वो शुरुआती स्टेशन ढूँढो जिससे पूरा चक्कर पूर्ण हो, या −1 लौटाएँ करो।

**ग्रीडी समझ:** अगर कुल गैस ≥ कुल लागत, तो समाधान ज़रूर है। चलता अधिशेष ट्रैक करो; जब भी यह नकारात्मक हो, उत्तर उसके **बाद** से शुरू होगा।

## काम शेड्यूलर

काम शेड्यूल करने हैं जिनमें एक जैसे काम के बीच `n` कूलडाउन हो। **ग्रीडी:** हमेशा सबसे बार-बार बाकी काम चुनो।

```
Tasks: A A A B B C, cooldown = 2
Schedule: A B C A B _ A
Total = 7
```

<ThinkAboutIt>काम शेड्यूलर में सबसे बार-बार काम पहले चुनने से निष्क्रिय स्लॉट कम क्यों होते हैं? अगर सबसे कम बार-बार पहले चुनें तो क्या गलत होगा?</ThinkAboutIt>

## फ़्रैक्शनल नैपसैक vs 0/1 नैपसैक

**फ़्रैक्शनल नैपसैक:** आइटम के टुकड़े ले सकते हो। ग्रीडी काम करता है - मान-परभार से सॉर्ट करो, सर्वश्रेष्ठ अनुपात पहले लो।

**0/1 नैपसैक:** आइटम पूरा लो या छोड़ो। ग्रीडी यहाँ **असफल** करता है क्योंकि भारी-बुट-वअलुअबल आइटम छोड़ना दो हल्के आइटम लेने से बुरा हो सकता है। इसके लिए डायनैमिक प्रोग्रामिंग चाहिए।

```
Items: (weight=3, value=4), (weight=2, value=3), (weight=2, value=3)
Capacity: 4

Greedy (best ratio first): item 1 (w=3, v=4) → 1 बचा → बाकी fit नहीं → value = 4
Optimal: items 2+3 (w=4, v=6) → value = 6 ✗ Greedy fail!
```

## ग्रीडी कब काम करता है?

✅ **काम करता है** जब ग्रीडी चयन गुण सिद्ध हो सके:
- अंतराल शेड्यूलिंग, हुफफपुरुष कोडिंग, न्यूनतम फैलाव ट्री, डिजकसटरअ's एल्गोरिदम

❌ **फैल** जब स्थानीय ऑप्टिमा वैश्विक ऑप्टिमा न बनाएँ:
- 0/1 नैपसैक, सबसे लंबा रास्ता, यात्रा सेल्सपुरुष

## ग्रीडी शुद्धता - एक्सचेंज तर्क

मानक तकनीक: मान लो एक सर्वोत्तम समाधान है जो ग्रीडी चयन **नहीं** इस्तेमाल करता। दिखाओ कि उसकी एक चयन को ग्रीडी चयन से **एक्सचेंज** करने पर समाधान बुरा नहीं होता। इससे साबित होता है ग्रीडी कम से कम उतना ही अच्छा है।

## ग्रीडी vs डायनैमिक प्रोग्रामिंग

| पहलू | ग्रीडी | डायनैमिक प्रोग्रामिंग |
|-------|--------|---------------------|
| चयन | हर कदम पर एक सर्वश्रेष्ठ चयन | सभी उप-समस्याएँ समझते हैं करो |
| पिछला फिर देखें? | कभी नहीं | हाँ - उप-नतीजे संग्रहीत करता है |
| गति | आमतौर पर तेज़ | स्थिति जगह पर निर्भर |
| शुद्धता | सिर्फ अगर सिद्ध हो | हमेशा (सही रूपरेखा पर) |

संदेह हो तो ग्रीडी से शुरू करो - सिद्ध नहीं कर पाए तो DP पर स्विच करो।

<FunFact>डिजकसटरअ's सबसे छोटा-रास्ता एल्गोरिदम ग्रीडी है - हमेशा निकटतम न देखे गए नोड प्रोसेस करता है। यह काम करता है क्योंकि एज भार नोननकारात्मक हैं, जो ग्रीडी चयन को सुरक्षित बनाता है।</FunFact>

<ThinkAboutIt>सिक्का मूल्यवर्ग [1, 3, 4] हैं और 6 के लिए बदलाव बनाना है। ग्रीडी 4+1+1=3 सिक्के चुनता है, लेकिन सर्वोत्तम 3+3=2 सिक्के है। इन मूल्यवर्ग में ग्रीडी चयन गुण क्यों टूटती है?</ThinkAboutIt>
