## हीप क्या है?

**हीप** एक पूर्ण बाइनरी ट्री है जहाँ हर पैरेंट **हीप गुण** पूरा करता है - या तो हमेशा छोटा (मिन-हीप) या हमेशा बड़ा (मैक्स-हीप) अपने चिल्ड्रन से। "पूर्ण" का मतलब हर स्तर भरा है, सिवाय शायद आख़िरी स्तर के जो बायाँ से दायाँ भरता है।

```
       1            Min-heap
      / \
     3   5
    / \
   7   4
```

पूर्ण होने की वजह से इसे **सपाट ऐरे** में संग्रहीत करते हैं - पॉइंटर की ज़रूरत नहीं। इंडेक्स `i` के लिए: बायाँ चाइल्ड = `2i + 1`, दायाँ चाइल्ड = `2i + 2`, पैरेंट = `(i - 1) // 2`।

## मिन-हीप vs मैक्स-हीप

| गुण | मिन-हीप | मैक्स-हीप |
|----------|----------|----------|
| रूट | सबसे छोटा एलिमेंट | सबसे बड़ा एलिमेंट |
| पैरेंट ≤ चिल्ड्रन? | ✅ हाँ | ❌ नहीं (≥) |
| निकालना देता है | न्यूनतम | अधिकतम |

Python का `heapq` डिफ़ॉल्ट में **मिन-हीप** है। मैक्स-हीप के लिए जोड़ना पर मान निगेट करो और निकालना पर वापस निगेट करो।

## जोड़ना और निकालना - कदम by कदम

**जोड़ना** - अंत पर पुश करो, फिर **बबल up** (पैरेंट से स्वैप करो जब तक छोटा हो):

```python
import heapq
h = [1, 3, 5, 7]
heapq.heappush(h, 2)  # h becomes [1, 2, 5, 7, 3]
```

**निकालना न्यूनतम** - रूट को आख़िरी एलिमेंट से स्वैप करो, आख़िरी पॉप करो, फिर **सिफ़्ट नीचे** (छोटे चाइल्ड से स्वैप):

```python
smallest = heapq.heappop(h)  # returns 1
```

दोनों क्रियाएँ **O(log n)** में चलते हैं क्योंकि ट्री की ऊँचाई log n है।

## हीपिफ़ाई - O(n) में हीप बनाओ

`heapq.heapify(arr)` एक लिस्ट को **जगह पर** O(n) में हीप बना देता है, O(n log n) नहीं। यह नीचे से ऊपर काम करता है, हर गैर-पत्ती नोड को सिफ़्ट नीचे करता है।

<FunFact>हीप बनाना O(n) है, O(n log n) नहीं। ज़्यादातर नोड नीचे के पास हैं और बमुश्किल सिफ़्ट नीचे करने पड़ते हैं - गणित रेखीय समय पर बैठता है है।</FunFact>

## प्रायोरिटी क्यू अमूर्तन

**प्रायोरिटी क्यू** हमेशा सबसे ऊँची प्राथमिकता आइटम पहले पहुँच करने देता है। हीप इसका सर्वश्रेष्ठ क्रियान्वयन हैं क्योंकि जोड़ना और निकालना दोनों O(log n) हैं। जब भी "अब तक का सर्वश्रेष्ठ आइटम दो" चाहिए, प्रायोरिटी क्यू इस्तेमाल करो।

## पैटर्न: टॉप-K समस्याएँ

> "अक्रमबद्ध ऐरे में K सबसे बड़े एलिमेंट ढूँढो।"

**आकार K का मिन-हीप** रखो। हर एलिमेंट पुश करो; अगर हीप K से बड़ा हो जाए, सबसे छोटी पॉप करो। जो बचे वो K सबसे बड़े हैं।

```python
import heapq
def top_k(nums, k):
    return heapq.nlargest(k, nums)
```

समय: **O(n लोग k)** - जब k ≪ n हो तो सॉर्टिंग से काफ़ी बेहतर।

## पैटर्न: मर्ज K क्रमबद्ध लिस्ट

हर लिस्ट का हेड मिन-हीप में पुश करो। सबसे छोटा पॉप करो, फिर उसी लिस्ट का अगला एलिमेंट पुश करो। जब तक सब लिस्ट खत्म न हो जाएँ। समय: **O(N लोग K)** जहाँ N कुल एलिमेंट हैं।

## पैटर्न: माध्यिका से डेटा स्ट्रीम

दो हीप बनाए रखना करो: निचला आधा के लिए **मैक्स-हीप** और ऊपरी आधा के लिए **मिन-हीप**। आकार में अधिकतम 1 का अंतर रखो। माध्यिका हमेशा एक या दोनों रूट पर होता है।

```
Lower half (max-heap): [1, 2, 3]  ← max = 3
Upper half (min-heap): [4, 5, 6]  ← min = 4
Median = (3 + 4) / 2 = 3.5
```

## शेड्यूलिंग समस्याएँ

हीप शेड्यूलिंग में कमाल करते हैं: मीटिंग कमरे (सबसे पहले अंत-समय ट्रैक करो), काम शेड्यूलिंग साथ कूलडाउन, या CPU जॉब क्यू। मूल बात: हीप कुशलता से ट्रैक करता है "अगला क्या खत्म होगा।"

<ThinkAboutIt>अगर न्यूनतम और अधिकतम दोनों कुशलता से चाहिए, तो एक हीप काफ़ी नहीं। कौन सा डेटा संरचना संयोजन इस्तेमाल करोगे?</ThinkAboutIt>

## हीप vs क्रमबद्ध ऐरे vs BST

| ज़रूरत | सबसे अच्छा चयन | क्यों |
|--------|-------------|-------|
| बार-बार न्यूनतम/अधिकतम निकालना | हीप | O(log n) जोड़ना + निकालना |
| स्थिर डेटा, एक बार सॉर्ट | क्रमबद्ध ऐरे | O(n log n) एक बार, O(1) पहुँच |
| रेंज क्वेरी + क्रम आँकड़े | संतुलित BST | O(log n) हर चीज़ के लिए |
| स्ट्रीम से टॉप-K | आकार K का हीप | O(n लोग k) कुल |

## जटिलता चीट शीट

| क्रिया | समय |
|-----------|------|
| जोड़ना | O(log n) |
| निकालना न्यूनतम/अधिकतम | O(log n) |
| देखना न्यूनतम/अधिकतम | O(1) |
| हीपिफ़ाई | O(n) |
| n आइटम से टॉप-K | O(n लोग k) |
