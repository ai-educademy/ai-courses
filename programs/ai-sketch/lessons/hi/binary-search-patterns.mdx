## क्लासिक बाइनरी सर्च - त्वरित समीक्षा

बाइनरी खोज हर कदम में खोज जगह आधा कर देता है। क्रमबद्ध ऐरे में n एलिमेंट में से लक्ष्य **O(log n)** समय में मिल जाता है।

```python
def binary_search(nums, target):
    lo, hi = 0, len(nums) - 1
    while lo <= hi:
        mid = (lo + hi) // 2
        if nums[mid] == target:
            return mid
        elif nums[mid] < target:
            lo = mid + 1
        else:
            hi = mid - 1
    return -1
```

सरल - लेकिन बाइनरी सर्च की असली ताकत क्रमबद्ध ऐरे से काफ़ी आगे है।

## खोज क्षेत्र की अवधारणा

बाइनरी खोज तब काम करता है जब किसी रेंज पर **मोनोटोनिक शर्त** हो। "ऐरे" का होना ज़रूरी नहीं - बस एक रेंज `[lo, hi]` चाहिए और एक फ़ंक्शन जो किसी सीमा पर `False` से `True` में बदले।

```
Search space:  [lo .................. hi]
Condition:      F  F  F  F  T  T  T  T
                          ^-- answer
```

<FunFact>बाइनरी खोज पहली बार 1946 में प्रकाशित हुआ, लेकिन पहला बुगमुक्त संस्करण 1962 में लिखा गया - 16 साल ोफफ-बयएक त्रुटियाँ के!</FunFact>

## बाइनरी सर्च on उत्तर

ऐरे में ढूँढने की जगह **उत्तर जगह** में खोज करो। सवाल पूछो: "क्या मैं नतीजा X हासिल कर सकता हूँ?" हाँ तो छोटा आज़माता है करो; नहीं तो बड़ा।

### उदाहरण: कोको खाना केले

कोको के पास `n` ढेर of केले हैं और `h` घंटे। **न्यूनतम खाना गति** ढूँढो जिससे वो समय पर खत्म कर सके।

```python
def min_speed(piles, h):
    lo, hi = 1, max(piles)
    while lo < hi:
        mid = (lo + hi) // 2
        hours = sum((p + mid - 1) // mid for p in piles)
        if hours <= h:
            hi = mid      # speed works, try slower
        else:
            lo = mid + 1  # too slow, go faster
    return lo
```

उत्तर जगह `[1, max(piles)]` है और शर्त मोनोटोनिक है - ज़्यादा गति = कम घंटे।

## घुमाया हुआ क्रमबद्ध ऐरे

एक क्रमबद्ध ऐरे किसी पिवट पर घुमाना हुआ: `[4, 5, 6, 7, 0, 1, 2]`। एक आधा हमेशा क्रमबद्ध रहता है। `mid` को `lo` से तुलना करके तय करना करो कौन सा आधा क्रमबद्ध है, फिर जाँच करो लक्ष्य उस क्रमबद्ध आधा में है या नहीं।

```
[4, 5, 6, 7, 0, 1, 2]
 L        M        R
Left half [4..7] sorted है।
Target 1 [4..7] में नहीं → right में search करो।
```

## पहला और आख़िरी उपस्थिति

**पहला** उपस्थिति ढूँढने के लिए, लक्ष्य मिलने पर रुको मत - `hi = mid` करो और बायाँ में खोज जारी रखो। **आख़िरी** के लिए `lo = mid + 1` करो और दायाँ में खोज करो।

इन दो खोजें से लक्ष्य का **गिनना** भी मिलता है: `last - first + 1`।

## शिखर एलिमेंट

वो एलिमेंट जो दोनों पड़ोसी से बड़ा हो। अक्रमबद्ध ऐरे में भी बाइनरी सर्च काम करता है: अगर `nums[mid] < nums[mid + 1]`, तो शिखर दाईं ओर में है; वरना बायाँ में। O(log n)।

<ThinkAboutIt>शिखर ढूँढना बाइनरी सर्च से क्यों काम करती है जबकि ऐरे क्रमबद्ध नहीं है? क्रमबद्ध क्रम की जगह कौन सी गुण काम कर रही है?</ThinkAboutIt>

## खोज in a 2D मैट्रिक्स

अगर पंक्तियाँ क्रमबद्ध हैं और हर पंक्ति का पहला एलिमेंट पिछली पंक्ति के आख़िरी से बड़ा है, तो मैट्रिक्स को `m × n` एलिमेंट की एक क्रमबद्ध ऐरे मानो। इंडेक्स `k` को पंक्ति `k // n`, कॉलम `k % n` में मैप करो।

## बिना लाइब्रेरी के वर्ग रूट

सबसे बड़ा पूर्णांक `x` ढूँढो जहाँ `x * x ≤ n`। खोज जगह: `[0, n]`। क्लासिक बाइनरी सर्च on उत्तर।

```python
def sqrt(n):
    lo, hi = 0, n
    while lo <= hi:
        mid = (lo + hi) // 2
        if mid * mid <= n:
            lo = mid + 1
        else:
            hi = mid - 1
    return hi
```

## "कम करना थे अधिकतम" पैटर्न

"बाँटना ऐरे सबसे बड़े योग" या "क्षमता to भेजना पैकेज भीतर D दिन" जैसे समस्याएँ सबसे खराब स्थिति **कम करना** करने कहते हैं। उत्तर मोनोटोनिक है: अगर क्षमता C काम करती है, तो C+1 भी करेगी। C पर बाइनरी सर्च करो।

## सार्वभौमिक टेम्पलेट

```python
lo, hi = min_possible, max_possible
while lo < hi:
    mid = (lo + hi) // 2
    if condition(mid):
        hi = mid        # mid works, try smaller
    else:
        lo = mid + 1    # mid fails, need larger
return lo
```

`hi = mid` vs `lo = mid` समायोजित करो - **पहले सही** ढूँढ रहे हो या **आख़िरी सही**।
