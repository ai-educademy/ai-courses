## रिकर्शन बुनियाद

रिकर्सिव फ़ंक्शन खुद को समस्या के **छोटे** संस्करण के साथ कॉल करता है जब तक **बेस स्थिति** न आ जाए जो चेन रोक दे।

हर रिकर्शन को दो चीज़ें चाहिए:
1. **बेस स्थिति** - सबसे सरल इनपुट जहाँ सीधे लौटाएँ करो।
2. **रिकर्सिव स्थिति** - समस्या तोड़ो और खुद को कॉल करो।

```python
def factorial(n):
    if n <= 1:        # base case
        return 1
    return n * factorial(n - 1)  # recursive case
```

## कॉल स्टैक - दृश्य रूप

हर रिकर्सिव कॉल कॉल स्टैक पर एक फ़्रेम पुश करती है। बेस स्थिति लौटाएँ होने पर फ़्रेम उल्टा क्रम में पॉप होते हैं।

```
factorial(4)
  → factorial(3)
    → factorial(2)
      → factorial(1) → returns 1
    ← returns 2
  ← returns 6
← returns 24
```

बेस स्थिति न हो तो स्टैक ओवरफ़्लो। Python की डिफ़ॉल्ट रिकर्शन सीमा 1,000 फ़्रेम है।

<FunFact>Python की डिफ़ॉल्ट रिकर्शन सीमा 1,000 जानबूझकर सावधान है। सयस.सेटरेकुरशनलिमिट() से बढ़ा सकते हो, लेकिन गहरा रिकर्शन के लिए इटरेटिव समाधान बेहतर हैं।</FunFact>

## फ़िबोनाची - क्लासिक जाल

Naïve रिकर्सिव फ़िबोनाची O(2ⁿ) है क्योंकि एक-सा उप-समस्याएँ बार-बार गणना होते हैं। मेमोइज़ेशन इसे O(n) समय और जगह में ठीक करता है।

```python
from functools import lru_cache

@lru_cache(maxsize=None)
def fib(n):
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)
```

## बैकट्रैकिंग - सब कोशिश करो, फिर अनडू करो

बैकट्रैकिंग रिकर्शन है एक मोड़ के साथ: **चयन बनाओ**, रिकर्स करो, फिर **चयन अनडू करो** और अगला विकल्प आज़माता है करो। सोचो जैसे भूलभुलैया समझते हैं कर रहे हो - आगे जाओ, बंद अंत मिला, वापस आओ, दूसरा रास्ता आज़माता है करो।

### बैकट्रैकिंग टेम्पलेट

```python
def backtrack(state, choices):
    if is_solution(state):
        result.append(state.copy())
        return
    for choice in choices:
        if is_valid(choice):
            state.add(choice)       # choose
            backtrack(state, ...)   # explore
            state.remove(choice)    # un-choose
```

यह **चुनें, समझते हैं, चयन हटाएँ** पैटर्न लगभग हर बैकट्रैकिंग समस्या की रीढ़ है।

## परम्यूटेशन

`[1, 2, 3]` के सभी क्रम बनाते करो। हर स्तर पर अनुपयोगी संख्या चुनें करो, रिकर्स करो, फिर चयन हटाएँ करो।

```
         []
      /   |   \
    [1]  [2]  [3]
    / \   ...
 [1,2] [1,3]
   |      |
[1,2,3] [1,3,2]  ... (6 total)
```

**n!** परम्यूटेशन होते हैं, तो समय जटिलता O(n × n!) है।

## कॉम्बिनेशन और सबसेट

**कॉम्बिनेशन (n चुनें k):** हर एलिमेंट पर शामिल करो या छोड़ें करो, लेकिन डुप्लिकेट से बचने के लिए सिर्फ आगे रिकर्स करो।

**सबसेट:** एक-सा विचार बिना आकार बाधा - रिकर्शन ट्री का हर नोड मान्य सबसेट है। **2ⁿ** सबसेट होते हैं।

<ThinkAboutIt>परम्यूटेशन n! नतीजे देते हैं जबकि सबसेट 2ⁿ। n=10 के लिए 3,628,800 vs 1,024 - बहुत बड़ा अंतर। क्यों?</ThinkAboutIt>

## N-क्वीन्स - वॉकथ्रू

N×N बोर्ड पर N क्वीन रखो जो एक-दूसरे को हमला न करें। N=4 के लिए:

```
. Q . .
. . . Q
Q . . .
. . Q .
```

**सटरअटेगय:** हर पंक्ति में एक क्वीन रखो। हर पंक्ति के लिए हर कॉलम आज़माता है करो। कॉलम, मुख्य डायगोनल, और एंटी-डायगोनल टकराव जाँच करो। सुरक्षित हो तो रखो और अगला पंक्ति पर रिकर्स करो। अटकें हो तो बैकट्रैक।

टकराव ट्रैक करो तीन सेट से: `cols`, `diag` (पंक्ति − कॉलम), `anti_diag` (पंक्ति + कॉलम)।

## सुडोकू सॉल्वर - अवधारणा

खाली सेल ढूँढो, अंक 1–9 आज़माता है करो। हर अंक के लिए पंक्ति, कॉलम, और 3×3 बॉक्स बाधाएँ जाँच करो। मान्य हो तो रखें करो और रिकर्स करो। कोई अंक काम न करे तो अनडू करो और बैकट्रैक। बाधाएँ की प्रूनिंग बहुत बड़ा खोज जगह को संभालने योग्य बनाती है।

## शब्द खोज in a ग्रिड

2D बोर्ड of अक्षर और लक्ष्य शब्द दिया है। हर सेल से शुरू करो और DFS से चार दिशाएँ में एक अक्षर मिलान करते जाओ। रिकर्शन में सेल देखे गए चिह्नित करो और **बैकट्रैक पर अनमार्क** करो।

## बैकट्रैकिंग की समय जटिलता

लागत **शाखा बनना घटक** (हर कदम पर चयन) और **गहराई** (समाधान तक कदम) पर निर्भर करती है। b शाखाएँ, d गहराई: O(bᵈ)।

| समस्या | शाखाएँ | गहराई | जटिलता |
|---------|-----------|-------|------------|
| परम्यूटेशन | n, n−1, … | n | O(n!) |
| सबसेट | 2 | n | O(2ⁿ) |
| N-क्वीन्स | ~n | n | O(n!) सबसे खराब स्थिति |

## प्रूनिंग से अनुकूलित करो

**प्रूनिंग** का मतलब ऐसी शाखाएँ छोड़ें करना जो असफल होंगी:
- N-क्वीन्स: पहले से भरी कॉलम छोड़ें करो।
- सुडोकू: बाधाएँ तोड़ना करने वाले अंक छोड़ें करो।
- कॉम्बिनेशन योग: बाकी योग < 0 हो तो छोड़ें।

अच्छी प्रूनिंग अव्यावहारिक खोज को तेज़ बना सकती है।
