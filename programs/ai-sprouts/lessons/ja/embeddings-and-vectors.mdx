# 埋め込み - AI が意味を理解する方法

トークン化後は、各トークンは単なる数字、つまり語彙のインデックスになります。しかし、インデックス 4,821 はモデルに *意味* について何も伝えません。 AI は、「王」と「女王」に関連性があること、または「銀行」が川岸や金融機関を意味することをどのようにして知るのでしょうか?答えは**埋め込み**です。

## ワンホットエンコーディングの問題

単純なアプローチでは、各単語を 1 つの `1` と数千の `0` を含むベクトルとして表します。 「猫」は`[0, 0, 1, 0, ..., 0]`、「犬」は`[0, 0, 0, 1, ..., 0]`になる可能性があります。

これには 2 つの致命的な欠陥があります。

- **類似点なし:** 「猫」と「犬」は、「猫」と「民主主義」と同じくらい互いに遠いです。エンコードではセマンティック情報はまったくキャプチャされません。
- **大規模なサイズ:** 50,000 語の語彙があるため、すべての単語に 50,000 次元のベクトルが必要です。非常に非効率的です。

## 単語の埋め込み - ジオメトリとしての意味

**埋め込み** は、各トークンを、たとえば 256 次元または 768 次元の密なベクトルにマップします。ワンホット ベクトルとは異なり、これらの次元はトレーニング中に学習され、意味をエンコードされます。

同様の文脈で使用される単語は、この空間では近くに集まります。 「子犬」が「子猫」の近くに着陸します。 「ロンドン」は「パリ」の近くに着陸します。空間の幾何学が「意味」なのです。

## Word2Vec - 王 − 男性 + 女性 = 女王

2013 年の **Word2Vec** 論文には、注目すべきことが示されています。大規模なテキスト コーパスでトレーニングすると、学習されたベクトルは算術関係を示します。

> `vector("king") − vector("man") + vector("woman") ≈ vector("queen")`

「男性」から「女性」への方向性はジェンダーの概念を捉えています。 「キング」に加えると「クイーン」に移ります。これはプログラムされたものではなく、言語のパターンから現れます。

他の例: `Paris − France + Italy ≈ Rome`、`bigger − big + small ≈ smaller`。

<FunFact>Word2Vec は、2013 年に Google の Tomáš Mikolov によって作成されました。この論文は 40,000 件以上引用されており、これまでに出版された NLP 論文の中で最も影響力のあるものの 1 つとみなされています。これは、生のテキストでトレーニングされた単純なニューラル ネットワークが驚くべき意味関係を学習できることを実証しました。
</FunFact>

## 埋め込み寸法

最新のモデルでは、さまざまな埋め込みサイズが使用されます。

|モデル |埋め込み寸法 |
|------|---------------------|
| Word2Vec | 100–300 |
|バート | 768 |
| GPT-3 | 12,288 |
| OpenAI テキスト埋め込み-3-large | 3,072 |

ディメンションが増えると、より細かい区別が捕捉されますが、より多くのメモリとコンピューティングが必要になります。人間を説明するのと同じように考えてください。3 つの次元 (身長、体重、年齢) が大まかなスケッチを与えます。 768 次元が詳細な肖像画を描きます。

## 単語から文へ

単語埋め込みは個々の単語を表しますが、多くの場合、文全体または文書全体を比較する必要があります。 **文埋め込み** (Sentence-BERT や OpenAI の埋め込み API などのモデルから) は、パッセージ全体を単一のベクトルに圧縮します。

「パスワードをリセットするにはどうすればよいですか?」 「ログイン資格情報を忘れました」と「ログイン資格情報を忘れました」には、単語がほとんど共有されていないにもかかわらず、非常によく似た文が埋め込まれています。埋め込みは語彙だけでなく *意図* も捉えます。

## 類似度の測定 - コサイン類似度

2 つの埋め込みを比較するには、**コサイン類似度** (2 つのベクトル間の角度のコサイン) を使用します。値の範囲は、-1 (反対方向) から +1 (同一方向) までです。

- 「幸せ」と「楽しい」: コサイン ≈ 0.85 (非常に似ています)。
- 「ハッピー」と「テーブル」: コサイン ≈ 0.10 (無関係)。
- 「愛」と「憎しみ」: コサインは ≈ 0.40 になる可能性があります (関係はありますが反対です)。

コサイン類似度はベクトルの大きさを無視し、純粋に方向に焦点を当てます。そこに意味が存在します。

<ThinkAboutIt>「愛」と「憎しみ」は意味的には正反対ですが、似たような文脈（感情、関係）で現れるため、適度なコサイン類似性を持っている可能性があります。このことから、純粋に単語の共起に基づいてトレーニングされた埋め込みの限界について何がわかるでしょうか?
</ThinkAboutIt>

## ベクトル データベース - 意味による検索

**ベクター データベース** には何百万もの埋め込みが保存され、最も類似した埋め込みが非常に高速に取得されます。キーワード一致 (「機械学習」を含むドキュメントを検索する) の代わりに、*意味* によって検索します (「AI 教育に関するドキュメントを検索」)。

一般的なベクトル データベースには次のようなものがあります。

- **Pinecone** - フルマネージドで、簡単に拡張できます。
- **Weaviate** - ハイブリッド検索 (ベクター + キーワード) を備えたオープンソース。
- **ChromaDB** - 軽量で、プロトタイピングに最適です。
- **pgvector** - PostgreSQL にベクトル検索を追加します。

これらのデータベースは、**HNSW** (Hierarchical Navigable Small World) などのアルゴリズムを使用して、ミリ秒単位で数十億のベクトルを検索します。

## RAG - 検索拡張生成

**RAG** は、現代の AI で最も重要なパターンの 1 つです。ベクトル検索と言語モデルを組み合わせます。

1. ドキュメントを**埋め込み**し、ベクター データベースに保存します。
2. ユーザーが質問するときは、クエリを**埋め込み**します。
3. ベクトル検索により、最も類似したドキュメント チャンクを **取得**します。
4. これらのチャンクをコンテキストとして言語モデルに **フィード**します。
5. モデルはデータに基づいた答えを**生成**します。

RAG を使用すると、言語モデルは再トレーニングすることなく、*あなたの* 特定のデータ (企業文書、製品カタログ、研究論文) に関する質問に答えることができます。モデルには参照できる実際のソースがあるため、幻覚が大幅に減少します。

## 実際の応用例

エンベディングは無数の現実世界のシステムを強化します。

- **セマンティック検索** - 正確な表現に関係なく、関連する結果を検索します。
- **推奨事項** - 類似性を埋め込むことで、「これを気に入ったユーザーは次も気に入っています...」。
- **クラスタリング** - 同様のサポート チケット、レビュー、ドキュメントを自動的にグループ化します。
- **異常検出** - クラスターから遠く離れた外れ値を特定します。
- **重複検出** - 大規模なコーパス全体でほぼ同一のコンテンツを検索します。

<FunFact>Spotify はオーディオ埋め込みを使用して曲を推奨します。各トラックは音響的特徴に基づいて埋め込まれており、埋め込み空間内で「似ている」曲、つまり近くのベクトルを見つけることで推奨が行われます。
</FunFact>

<ThinkAboutIt>オンラインショップにあらゆる商品を埋め込んだ場合、購入履歴に頼らずに「この商品を見た人はこんな商品も好きかも」というレコメンデーションシステムをどのように構築できるでしょうか?
</ThinkAboutIt>

## 重要なポイント

- **エンベディング**は、意味が幾何学になる高密度ベクトル表現です。
- 同様の概念が集まって集まります。関係性が方向性として現れます。
- **コサイン類似度**は、2 つの意味がどれだけ近いかを測定します。
- **ベクター データベース** により、大規模な意味による検索が可能になります。
- **RAG** はベクトル検索と言語モデルを組み合わせて、独自のデータからの質問に答えます。
