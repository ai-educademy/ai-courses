# トークン化 - AI がテキストを読み取る方法

ニューラル ネットワークは数値を処理します。彼らはあなたと同じように「こんにちは」という言葉を読むことができません。言語モデルがテキストを処理できるようにするには、テキストを **トークン** と呼ばれる小さな数値部分に分割する必要があります。この一見単純なステップは、AI が言語をどのように理解するか、そして誤解するかに重大な影響を及ぼします。

## なぜ AI は文字を読むことができないのでしょうか?

最も単純なアプローチ: 各文字をトークンとして扱います。 「こんにちは」は`['H', 'e', 'l', 'l', 'o']` - 5 つのトークンになります。

問題？単語は途方もなく長いシーケンスになります。 500 ワードのエッセイは 2,500 文字以上のトークンになる可能性があります。 Transformer モデルはシーケンスの長さに応じて二次的にスケールするため、これは計算的に非常に困難です。さらに悪いことに、個々の文字にはほとんど意味がありません。モデルは、「c」、「a」、「t」が一緒になって毛皮で覆われた動物を意味することを学習する必要があります。

## 単語レベルのトークン化

対極: 各単語は 1 つのトークンです。 「猫が座った」は`['The', 'cat', 'sat']`になり、コンパクトで意味のあるものになります。

しかし、これは**語彙の爆発**という別の問題を引き起こします。英語だけでも何十万もの単語があります。スペルミス、専門用語、コードが追加されると、語彙は管理できなくなります。語彙にない単語はすべて未知の `[UNK]` トークンとなり、理解の行き止まりになります。

<ThinkAboutIt>単語レベルのトークンを使用するモデルが初めて「ChatGPT」に遭遇し、それが語彙に含まれていない場合、それは `[UNK]` になります。これは、新しいテクノロジーについて議論するモデルの能力にどのような影響を与える可能性がありますか?
</ThinkAboutIt>

## スイート スポット - サブワードのトークン化

最新の言語モデルは、文字と単語の間にある **サブワード トークン化** を使用します。一般的な単語はそのまま残ります (「the」、「and」) が、まれな単語は意味のある部分 (「un」 + 「believ」 + 「able」) に分割されます。

これにより、モデルがこれまで見たことのない単語であっても、あらゆるテキストを処理しながら、管理可能な語彙 (通常は 32,000 ～ 100,000 トークン) が得られます。

## バイト ペア エンコーディング (BPE) - ステップバイステップ

**BPE** は GPT モデルの背後にあるアルゴリズムです。語彙を構築する方法は次のとおりです。

1. **個々の文字から始めます**: `{'h', 'e', 'l', 'o', 'w', 'r', 'd', ' '}`。
2. トレーニング テキスト内で最も頻繁に出現する隣接するトークンのペアを **数えます**。
3. 最も頻繁に使用されるペアを新しいトークンに **マージ**します。 「l」+「o」が最も多く出現する場合は、「lo」を作成します。
4. 希望の語彙数に達するまで、**手順 2 ～ 3* を繰り返します。

**作業例** テキスト「low lower lowers」:

|ステップ |最も頻繁に使用されるペア |新しいトークン |語彙力が伸びる |
|------|------|-----------|------|
| 1 | l + o |そうだ | ...ほら... |
| 2 |ロー + ワット |低い | ...低い... |
| 3 | e + r |えー | ...えっと... |
| 4 |低い + e |ロウ | ...ロウ... |

十分なマージが行われると、一般的な単語や単語の断片がデータから自然に現れます。

<FunFact>BPE はもともと 1994 年にデータ圧縮アルゴリズムとして発明されました。 2015 年に Sennrich らによって NLP 用に再利用されました。 - 分野を超えたアイデアの美しい例。
</FunFact>

## 他のトークン化方法

### ワードピース

BERT および関連モデルで使用されます。 BPE と似ていますが、最も頻繁に使用されるペアをマージする代わりに、トレーニング データの **尤度** を最大化するペアをマージします。サブワード部分には接頭辞 `##` が付きます (例: 「遊び」→ `['play', '##ing']`)。

### 文の一部

入力を生のバイト ストリームとして扱います。スペースによる事前のトークン化は行われません。これは、単語間にスペースを使用しない日本語や中国語のような言語では非常に重要です。 GPT-4 と LLaMA は SentencePiece スタイルのアプローチを使用します。

## GPT-4 がテキストをトークン化する方法

GPT-4 は、語彙に約 100,000 個のトークンを含む **cl100k_base** と呼ばれる BPE バリアントを使用します。いくつかの驚くべき動作:

- 「Hello world」→ 2 つのトークン (`Hello`、` world` - スペースが付加されていることに注意してください)。
- 「不可分性」→ 4 トークン (`ind`、`iv`、`isibility` - レアな単語を分割します)。
- 単一の絵文字 🎉 → 多くの場合、1 ～ 3 個のトークン。
- Python コード `def hello():` → 各キーワードとシンボルは通常、独自のトークンです。

## 語彙サイズのトレードオフ

|語彙のサイズ |長所 |短所 |
|--|------|------|
|小 (8k) |モデルが小さくなり、埋め込みが少なくなる |シーケンスが長くなり、処理が遅くなる |
|大規模 (100k+) |短いシーケンス、より豊富なトークン |より大きな埋め込みテーブル、より多くのメモリ |

適切なバランスを見つけることは、モデルの速度、メモリ、機能に影響を与えるエンジニアリング上の決定です。

## 多言語の課題

主に英語のテキストでトレーニングされたトークナイザーは**偏っています**。ヒンディー語またはアラビア語の同じ文には、英語の同等の文よりも 3 ～ 5 倍多くのトークンが必要になる場合があります。これは、これらの文字がトレーニング データで過小評価されているためです。これはつまり：

- 英語以外のユーザーはすぐにコンテキスト制限に達します。
- 英語以外のテキストの場合、単語ごとの API コストが高くなります。
- このモデルでは、英語以外の推論のための「思考スペース」が少なくなります。

## トークンのカウントとコストへの影響

GPT-4、Claude、または Gemini へのすべての API 呼び出しはトークンごとに課金されます。トークン化を理解すると、次のことが役立ちます。

- 大規模なジョブを実行する前に **コストを見積もります**。
- **プロンプトを最適化** - 同じ意味のプロンプトを短くすることでコストを節約します。
- **コンテキスト ウィンドウを尊重する** - GPT-4 Turbo は 128k トークンを受け入れます。これを超えると、入力が自動的に切り捨てられます。

英語の大まかな経験則: **1 トークン ≈ 3/4 の単語**、または約 4 文字。

## 重要なポイント

- トークン化は、生のテキストをモデルが処理できる数値トークンに変換します。
- **BPE** は、最も頻繁に使用される文字のペアを繰り返しマージすることで語彙を構築します。
- サブワードのトークン化により、語彙サイズとあらゆるテキストを処理できる能力のバランスがとれます。
- トークナイザーのバイアスにより、英語以外の言語はコストと機能の点で不利になります。
- トークンを理解すると、コストを見積もり、プロンプトを最適化するのに役立ちます。
