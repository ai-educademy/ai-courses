# 大規模な言語モデルを理解する 🔤

ChatGPT、クロード、ジェミニ、ラマ — 彼らはどこにでもいます。しかし、これらはあなたのメッセージに応答するときに実際に何をしているのでしょうか?答えはあなたが予想しているよりもシンプルであり、さらに頭を悩ませるものです。

大規模言語モデル (LLM) はその中核で、**次のトークンを予測する**という 1 つのことを行っています。何度も何度も。それでおしまい。それでも、この単純なプロセスから、コードを記述し、量子物理学を説明し、詩を作曲し、驚くほど一貫した会話を行う能力が生まれます。

どのように開梱してみましょう。

---

## 🔡 まず: トークンとは何ですか?

モデル自体に到達する前に、LLM が動作する言語の単位である **トークン** を理解する必要があります。

トークンは正確には単語ではありません。これは、言語内で頻繁に出現する、1 つの単位として扱う価値のある **テキストの塊** に似ています。英語では、「the」、「and」、「is」などの一般的な単語は単一のトークンです。長くて珍しい単語は分割される可能性があります。「特別な」が「特別な」+「普通の」になる可能性があります。多くの場合、数字と句読点はそれ自体がトークンです。

大まかな経験則: 英語では **1 トークン ≈ 0.75 単語**。

なぜ言葉だけを使わないのでしょうか？トークン化では次の処理が行われるため、
- 単語構造が異なる複数の言語
- コード (空白と記号の重要性が異なる場合)
- 新しい単語、名前、専門用語
- 数学的表現

LLM にメッセージを入力すると、メッセージはすぐに一連のトークン ID (通常は 30,000 ～ 100,000 トークンの語彙内の数値) に変換されます。

<FunFact>フロンティア LLM は、一般的に約 100,000 トークン以上に及ぶトークン語彙を使用します。英語全体では一般的に使用される単語が約 170,000 語ありますが、LLM のトークン語彙は多くの言語、コード構文、絵文字、専門用語も同時にカバーします。
</FunFact>

## 🎯 中心的なタスク: 次に何が起こるかを予測する

すべての LLM の基本的なトレーニング目標は次のとおりです。

> 一連のトークンが与えられた場合、**次に考えられる各トークンの確率を予測します**。

トレーニング中、モデルには次のような数十億の例が表示されます。
- 「猫は ___ の上に座っていました」 → (おそらく: マット、床、ソファ、屋根...)
- "def Calculate_sum(a, b):\n return ___" → (おそらく: a + b)
- 「フランスの首都は ___ です」 → (ほぼ確実にパリです)

十分な例を確認することで、モデルは言語の統計的パターンを学習します。単語ごとに学習するだけでなく、意味、因果関係、コンテキストの深い構造も学習します。

テキストを生成するとき、モデルは次のことを行います。
1. 以前のすべてのトークンを確認します
2. 語彙全体にわたる確率分布を出力します。
3. その分布からトークンをサンプリングします (「温度」によって制御されるランダム性を伴います)
4. そのトークンをシーケンスに追加します
5. リピート

LLM の応答で読み取られるすべての単語は、一度に 1 つのトークンが生成され、それぞれはその前にあるすべてのものから情報を得ます。

## 🔄 トランスフォーマーのアーキテクチャ

最新の LLM を可能にしたアーキテクチャは **Transformer** と呼ばれ、Google 研究者によって 2017 年の画期的な論文「Attending is All You Need」で紹介されました。

Transformers が登場する以前は、言語モデルは、各単語の下に指を置いてゆっくりと文を読むように、テキストを単語ごとに順番に処理していました。これでは時間がかかり、文内で遠く離れた単語を接続することが困難でした。

トランスフォーマーは **すべてのトークンを同時に処理**し、すべてのトークンを他のすべてのトークンと直接対話させます。これは **並列処理** と呼ばれ、これが並列処理が非常に強力である理由の 1 つです。

しかし、本当の魔法は**注意メカニズム**にあります。

## 👁️ 注意: モデルの焦点の合わせ方

この文を読んだところを想像してみてください。

> *「トロフィーは大きすぎてスーツケースに入りませんでした。」*

「それ」とは何を指すのでしょうか？トロフィー。あなたは、「それ」を解釈する際に、すぐに遡って「トロフィー」に重点を置いたので、それを知っていました。

**アテンション メカニズム** により、モデルはまさにこれを実行できます。トークンごとに、コンテキスト内の他のすべてのトークンにどれだけの「注意」を払うかを計算します。それは次のように尋ねます。

> *「この単語を理解するには、シーケンス内の他のどの単語が最も関連していますか?」*

これらの注意の重みはトレーニング中に学習されます。このモデルは、代名詞を処理するときに、文の前半にある名詞が高い注目に値することを学習します。動詞を処理するとき、主語は非常に注目に値します。

### マルチヘッドアテンション

最新のトランスフォーマーは **マルチヘッド アテンション** を使用します。多くのアテンション計算を並行して実行し、それぞれが異なる種類の関係を探します。
- 1 つの「頭」が文法関係 (主語と動詞の一致) を追跡する可能性があります
- 別のユーザーが共参照 (代名詞が何を参照しているか) を追跡する可能性があります。
- 別の方法では、意味の類似性 (どの単語が同じようなことを意味するか) を追跡する可能性があります。

すべてのヘッドの出力を組み合わせて、コンテキスト全体に対する各トークンの関係についての豊富な多次元の理解を構築します。

<FunFact>GPT-3 には、96 個のレイヤーにわたって 96 個のアテンション ヘッドがあります。つまり、処理の各層で、単語間の関係に関する 96 の異なる「視点」が同時に計算されます。各頭が何を学習したかを完全に理解している人は誰もいません。これは、大規模なニューラル ネットワークの多くの謎の 1 つです。
</FunFact>

## 📏 コンテキスト ウィンドウ: どれくらいのことを記憶できるでしょうか?

**コンテキスト ウィンドウ** は、LLM が一度に考慮できるトークンの最大数です。これをモデルの作業記憶と考えてください。

初期の GPT モデルには、2,048 トークン (約 1,500 ワード) のコンテキスト ウィンドウがありました。現在のフラッグシップモデルはこれを数十万トークンにまで拡大し、最大規模のモデルは 100 万トークン以上をうたっています。小説 1 冊や大規模なコードベース全体を一度に保持するのに十分な量です。

コンテキスト ウィンドウ内のすべてのものは、すべてのレイヤーのすべての注目者がアクセスできます。その外側にあるものはすべてモデルには見えません。人間のようなあいまいな「薄れていく記憶」はなく、厳密に遮断されます。

これが、LLM との会話が非常に長くなると失敗する可能性がある理由です。最終的には、会話の初期部分がコンテキスト ウィンドウから外れてしまいます。

## 🏋️ トレーニング: スケールがすべて

LLM は、本当に驚くべき量のテキストでトレーニングされます。
- **GPT-3** は、約 3,000 億のトークン (約 570GB のテキスト) でトレーニングされました
- **フロンティアのクローズド モデル** は通常、トレーニングの詳細を秘密にしていますが、推定では数兆個のトークンが示唆されています
- **Llama 4 Scout** は約 40 兆トークンのマルチモーダル データでトレーニングされました

トレーニング データは、Web クロール (Common Crawl)、書籍、Wikipedia、コード リポジトリ、学術論文などから取得されます。これは、基本的にインターネット上に書かれたテキストのかなりの部分を占めます。

トレーニングのコンピューティング コストは膨大です。GPT-3 のトレーニングにはコンピューティングだけで推定 460 万ドルのコストがかかりました。現在のフロンティア モデルのトレーニングは、データ、GPU、エネルギー、エンジニアリングを含めると数億ドルかかることがあります。

### 緊急能力: サプライズ

モデルが大きくなると、何か奇妙なことが起こります。**創発的な能力**が開発されます。これは、明示的にトレーニングされておらず、小規模なモデルには現れず、大規模になると突然現れるように見える能力です。

GPT-2 (2019) では、一貫した段落をほとんど書くことができませんでした。GPT-3 (2020) は、エッセイを書き、論理パズルを解き、ほとんど見たことのない言語を翻訳することができました。後のフロンティア モデルは、難しい医療、法律、コーディングのベンチマークに合格できます。

これらは明示的にプログラムされたものではありません。彼らはスケールから現れました。

<ThinkAboutIt>LLM は何も「経験」したことがありません。日の出を見たことも、寒さを感じたことも、リアルタイムで会話したこともありません。それでも、これらのことについて説得力を持って書くことができるのは、それらについての何百万もの人間による記述を処理しているからです。これは、モデルがこれらの経験を「理解」していることを意味するのでしょうか、それとも根本的に異なることを行っているのでしょうか?
</ThinkAboutIt>

## 🎛️ 予測マシンから役立つアシスタントへ

生のネクストトークン予測は、与えられたテキストを継続する何かを生成します。これは補完には役立ちますが、会話には役立ちません。

LLM を役立つアシスタントにするには、**RLHF (ヒューマン フィードバックからの強化学習)** と呼ばれる 2 番目のトレーニング フェーズを通過します。

1. モデルはプロンプトに対して多くの可能な応答を生成します
2. 人間の評価者が回答を最高から最低までランク付けします
3. 「報酬モデル」は人間の好みを予測することを学習します
4. LLM は、報酬モデルが高く評価する応答を生成するように微調整されています

これが、生の言語モデルが、あなたが対話する ChatGPT または Claude になる方法です。役に立ち、無害で、比較的誠実です。

## 🔬 LLM にできることとできないこと

**LLM は次の点で非常に優れています:**
- 流暢で状況に応じて適切なテキストを生成する
- 言語間の翻訳
- コードを書いて説明する
- 長い文書を要約する
- 複雑な指示に従う
- 創造的なタスク: 物語、詩、ブレインストーミング

**LLM は依然として次のことに苦労しています。**
- 正確な算術演算 (電卓ではありません)
- 知らないことを確実に知る（幻覚）
- トレーニング終了後のイベントの最新情報を入手する
- エラーのない長い複数ステップの推論
- 真の因果関係の推論と統計的相関関係

これらの制限を理解することは悲観論ではありません。LLM を効果的に使用し、弱点を補いながら長所を生かしたシステムを構築する方法です。
